# Формат записей

Документацию читают и люди, и агенты, а проверяет встроенная команда `wk docs check`.
Поэтому формат строгий: скрипт по нему находит определения, ссылки и ошибки.

## Два способа определить ID

### 1. Карточка — для крупных фактов (API, таблица, сервис, класс, модель…)

```markdown
### TBL-orders — Заказы
status: implemented | owner: SVC-orders | store: RES-pg-main

- поле: значение
- поле: значение

(таблицы, диаграммы, короткий текст «почему»)
```

- Заголовок `##` или `###`: сначала ID, потом ` — ` и короткое человеческое название.
- **Первая непустая строка после заголовка — мета-строка**: пары `ключ: значение` через ` | `.
- Карточка заканчивается на следующем заголовке того же или более высокого уровня.

### 2. Строка таблицы — для мелких однотипных фактов (зависимости, ошибки, настройки, термины)

```markdown
| id | package | version | status |
|---|---|---|---|
| DEP-py-fastapi | fastapi | ^0.115 | implemented |
```

- Первая колонка таблицы называется `id` — тогда каждая строка с ID в ней считается определением.
- Колонки `status` и `owner` в такой таблице читаются так же, как в мета-строке.
- Таблица, которая только **перечисляет** уже определённые ID (сводка в `INDEX.md`, список
  зависимостей компонента), не должна начинаться с колонки `id` — назови её `компонент`, `ресурс`, `ref`.
  Иначе скрипт увидит второе определение того же ID.

## Обязательные поля мета-строки

| поле | для каких типов | значения |
|---|---|---|
| `status` | все, кроме TERM | `draft` → `planned` → `implemented` → `deprecated`; для ADR: `proposed`, `accepted`, `superseded`; для Q: `open`, `resolved`; для RISK: `open`, `accepted`, `closed` |
| `owner` | API, EVT, CLI, DTO, FMT, PRM, TBL, KV, BKT, MOD, CLS, JOB, CFG | ID компонента (`SVC-…` или `LIB-…`) |
| `replaced_by` | когда `status: deprecated` и есть замена | ID замены |

Что значат статусы:
- `draft` — идея, обсуждается, код по ней писать **нельзя**;
- `planned` — утверждено, можно реализовывать;
- `implemented` — есть в коде, в коде стоит маркер `doc: <ID>`;
- `deprecated` — больше не использовать; живёт, пока на него есть ссылки.

## Ссылки

- На другой факт ссылаемся просто его ID: `пишет в TBL-orders`. Обратные кавычки можно: `` `TBL-orders` ``.
- Скрипт сам находит все ссылки и строит обратные связи («кто использует») в `_meta/registry.md`.
- Ссылка на часть: `TBL-orders#status`. На группу: `API-orders.*`.
- Ссылки на код — путь от корня репозитория в обратных кавычках: `` `services/orders/cmd/main.go` ``.
  Номера строк не пишем: они устаревают. Точное место в коде находится по маркеру `doc: <ID>`.

## Единая система типов

Проект на нескольких языках, поэтому в контрактах (DTO, TBL, CFG) типы пишем **нейтрально**,
а не на Go/Python/TS/Rust. Перевод в конкретный язык — работа кодогенерации или агента.

| тип | смысл | Go | Python | TypeScript | Rust |
|---|---|---|---|---|---|
| `string` | строка UTF-8 | string | str | string | String |
| `int32` / `int64` | целое | int32 / int64 | int | number / bigint | i32 / i64 |
| `float64` | дробное (не для денег) | float64 | float | number | f64 |
| `decimal(p,s)` | точное число, деньги | decimal.Decimal | Decimal | string | rust_decimal::Decimal |
| `bool` | да/нет | bool | bool | boolean | bool |
| `uuid` | UUID | uuid.UUID | UUID | string | uuid::Uuid |
| `timestamp` | момент времени, всегда UTC | time.Time | datetime (aware) | string (ISO 8601) | DateTime&lt;Utc&gt; |
| `date` | дата без времени | civil.Date | date | string | NaiveDate |
| `duration` | длительность | time.Duration | timedelta | number (ms) | Duration |
| `bytes` | бинарные данные | []byte | bytes | Uint8Array | Vec&lt;u8&gt; |
| `enum(a\|b\|c)` или `enum(STATE-x)` | одно из значений | const + type | Enum | union | enum |
| `T[]` | список | []T | list[T] | T[] | Vec&lt;T&gt; |
| `map<K,V>` | словарь | map[K]V | dict[K,V] | Record&lt;K,V&gt; | HashMap&lt;K,V&gt; |
| `T?` | может отсутствовать / null | *T | T \| None | T \| null | Option&lt;T&gt; |
| `json` | произвольный JSON (избегать) | json.RawMessage | dict | unknown | serde_json::Value |
| `DTO-x` | вложенная структура | — | — | — | — |

Если проекту нужна таблица точнее (конкретные библиотеки для decimal, uuid) — правим её здесь, в одном месте.

## Как писать, чтобы агент не путался

1. **Что и зачем, а не как.** Не пересказываем код. Пишем контракт, правила, причины.
2. **Таблица лучше списка, список лучше абзаца.** Абзац — только для «почему».
3. **Без «и т.д.», «и прочее», «как обычно».** Если список неполный — так и пишем: `(неполный, см. Q-…)`.
4. **Каждое неочевидное «нельзя» записываем явно**: `must not: читать TBL-orders напрямую, только через API-orders.get`.
5. **Неизвестное не выдумываем.** Не знаем — заводим `Q-…` и ссылаемся на него.
6. **Числа с единицами**: `30s`, `10 rps`, `50 MB`, `7d`.
7. **Время всегда UTC**, расписания cron — с часовым поясом.

## Бюджет объёма

Цель — агент понимает систему по ~2000 строкам, не читая код.

| файл | максимум |
|---|---|
| `INDEX.md` | 150 строк |
| `components/<c>/component.md` | 120 строк |
| любой другой файл | 400 строк — дальше делим на несколько файлов |

Скрипт предупреждает о превышении. Документируем **не всё подряд**:
- MOD — каждый модуль верхнего уровня внутри компонента;
- CLS — только то, что используют снаружи модуля, и то, где живёт важная логика или правило;
- DEP — только прямые зависимости из манифестов, не транзитивные.
